ОПИСАНИЕ ИГРОВОГО ДАТАСЕТА «ИСТОРИЧЕСКИЙ АРХИВ»
Версия: 23 ноября 2026 года

ФАЙЛ
historical_archive_data.xlsx

НАЗНАЧЕНИЕ
Игровая база исторической викторины VK Mini Apps. Правильный ответ открывает один факт о конкретной личности. Факты не показываются игроку заранее.

СОСТАВ
390 исторических личностей
10 категорий
2 681 активный исторический факт
2 254 подготовленных вопроса с четырьмя вариантами ответа
427 фактов без автоматически сгенерированного вопроса

СОДЕРЖИМОЕ EXCEL
«Инструкция» — описание правил использования и текущих ограничений.
«Персоны» — идентификаторы, имена, категории и количество фактов/вопросов.
«Факты» — идентификаторы, поля, значения, исторические источники и статусы проверки.
«Вопросы» — текст, четыре варианта, номер правильного ответа, ID личности и ID открываемого факта.
«Широкий формат» — одна строка на личность, восстановленная из реестра.
«Проверка» — результаты структурного контроля данных.

КАК ИСПОЛЬЗОВАТЬ
1. Для коллекции брать сведения из листа «Факты» по ID личности.
2. Для викторины брать готовые вопросы из листа «Вопросы».
3. После правильного ответа открывать факт по значению «Открываемый ID факта».
4. Неправильный ответ не открывает факт.
5. Не показывать игроку неоткрытые сведения о личности заранее.
6. Не вводить дополнительные признаки приблизительных дат или специальные правила сравнения: спорные значения удалены или заменены.

ЧТО ПРОВЕРЕНО
— наличие 390 уникальных личностей и 10 категорий;
— отсутствие пустых обязательных полей в фактах;
— отсутствие дублирующихся пар «ID личности — поле»;
— минимум три факта у каждой личности;
— как минимум один готовый вопрос у каждой личности;
— четыре разных имени и один назначенный правильный ответ в каждом готовом вопросе;
— ссылки вопросов на открываемые факты.

ОГРАНИЧЕНИЯ
Автоматическая структурная проверка не заменяет редакторскую вычитку каждого вопроса и проверку правильности ответов в интерфейсе. Перед запуском необходимо интеграционное тестирование.

Исходная широкая таблица при финальной сборке была недоступна; соответствующий лист восстановлен из проверенного реестра и не обязан совпадать с первоначальной схемой колонок.

Исторические источники указаны непосредственно в листе «Факты». Дополнительная независимая проверка всех источников на этапе загрузки в GitHub не проводилась.
