ОПИСАНИЕ ИГРОВОГО ДАТАСЕТА «ИСТОРИЧЕСКИЙ АРХИВ»
Версия: 26 ноября 2026 года (после редакторской вычитки)

ФАЙЛЫ
historical_archive_data.xlsx — основной датасет для редактирования и проверки исторических данных.
historical_archive_data.json — игровая версия для подключения к приложению; формируется из Excel.

НАЗНАЧЕНИЕ
Игровая база исторической викторины VK Mini Apps. Правильный ответ открывает один факт о конкретной личности. Факты не показываются игроку заранее.

СОСТАВ
390 исторических личностей
10 категорий
2 681 активный исторический факт
2 681 подготовленный вопрос с четырьмя вариантами ответа
0 фактов без вопроса (покрытие 100%)

СОДЕРЖИМОЕ EXCEL
«Инструкция» — описание правил использования и текущих ограничений.
«Персоны» — идентификаторы, имена, категории и количество фактов/вопросов.
«Факты» — идентификаторы, поля, значения, исторические источники и статусы проверки.
«Вопросы» — текст, четыре варианта, номер правильного ответа, ID личности и ID открываемого факта.
«Широкий формат» — одна строка на личность, восстановленная из реестра.
«Проверка» — результаты структурного контроля данных.

СОДЕРЖИМОЕ JSON (schemaVersion: 1)
project — название игры.
source — имя исходного Excel и контрольная сумма Git (gitBlobSha).
categories — ID, название и количество личностей в категории.
persons — ID личности, имя, categoryId, количество фактов и вопросов.
facts — ID факта, personId, поле (field) и значение (value).
questions — ID вопроса, categoryId, field, text, options (имена), optionPersonIds (ID в том же порядке), correctOptionIndex (индекс от 0 до 3), correctPersonId и factId.
Исторические источники и статусы проверки остаются в Excel.

КАК ИСПОЛЬЗОВАТЬ
1. В приложении загружать JSON как локальный ресурс. Для коллекции брать facts по personId, для категорий — categories и persons по categoryId.
2. Для обычной викторины брать готовые вопросы из questions. Порядок options и optionPersonIds должен совпадать; correctOptionIndex отсчитывается от нуля.
3. После правильного ответа открывать факт по factId.
4. Неправильный ответ не открывает факт.
5. Не показывать игроку неоткрытые сведения о личности заранее.
6. Не вводить дополнительные признаки приблизительных дат или специальные правила сравнения: спорные значения удалены или заменены.
7. Исторические данные редактировать в Excel, затем заново формировать JSON и проверять соответствие идентификаторов, фактов, вопросов и вариантов ответа. Не редактировать игровую копию независимо от Excel.

ЧТО ПРОВЕРЕНО
— наличие 390 уникальных личностей и 10 категорий;
— отсутствие пустых обязательных полей в фактах;
— отсутствие дублирующихся пар «ID личности — поле»;
— минимум три факта у каждой личности;
— ровно один готовый вопрос на каждый из 2 681 факта;
— четыре разных имени и один назначенный правильный ответ в каждом готовом вопросе;
— ссылки вопросов на открываемые факты;
— совпадение данных личностей, фактов, текстов вопросов, порядка вариантов и правильных ответов между Excel и JSON;
— четыре разные личности одной категории в каждом вопросе JSON и корректные ссылки на их ID.

РЕДАКТОРСКАЯ ВЫЧИТКА
Проведена редакторская вычитка 427 добавленных вопросов. По её результатам изменены формулировки 86 вопросов, уточнены 3 исторических факта и исправлена 1 опечатка в фактах. Первоначальные 2 254 вопроса, идентификаторы и варианты ответов сохранены. Уточнения внесены одновременно в Excel и JSON; количество фактов и вопросов не изменилось.

ОГРАНИЧЕНИЯ
Автоматическая структурная проверка не заменяет проверку однозначности ответов. Независимая историческая проверка всех сведений не проводилась. Перед запуском необходимо проверить однозначность вопросов при случайном подборе вариантов ответа и провести интеграционное тестирование приложения.

Исходная широкая таблица при финальной сборке была недоступна; соответствующий лист восстановлен из проверенного реестра и не обязан совпадать с первоначальной схемой колонок.

Исторические источники указаны непосредственно в листе «Факты». Дополнительная независимая проверка всех источников на этапе загрузки в GitHub не проводилась.
