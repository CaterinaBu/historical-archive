# Диалоги игры «Исторический архив»

Этот каталог содержит сюжетные тексты игры отдельно от компонентов интерфейса и логики сохранения прогресса.

## Содержимое

- `istoricheskiy_arhiv_dialogues.json` — утверждённый сценарный набор: **10 сюжетных линий по 30 глав (300 глав)**, пролог, общий финал и справочник персонажей.
- `README.md` — назначение файлов, структура данных и рекомендации по интеграции.

## Структура JSON

Корневые поля:

| Поле | Содержание |
| --- | --- |
| `schemaVersion` | Версия формата данных (сейчас `1`) |
| `project` | Название проекта |
| `characters` | Справочник персонажей по стабильным ключам (`player`, `elena`, `alice` и др.) |
| `prologue` | Обучающие карточки и параметры учебного вопроса |
| `storylines` | Список из десяти сюжетных линий; в каждой — 30 глав |
| `finale` | Карточки и завершающее сообщение основного сюжета |

Схема вложенности: `storylines[] → chapters[] → cards[] → lines[]`. У каждой реплики есть `speaker` (ключ из `characters`) и `text`. В главах может быть **несколько карточек** — отображение не должно предполагать одну карточку на главу. Для однозначной адресации используйте `id`, а не позицию в массиве.

Пример чтения в JavaScript:

```js
import dialogues from './istoricheskiy_arhiv_dialogues.json';

const storyline = dialogues.storylines.find(line => line.id === 'line_09');
const chapter = storyline.chapters.find(ch => ch.number === 1);
const firstLine = chapter.cards[0].lines[0];
const character = dialogues.characters[firstLine.speaker];
console.log(character.name, firstLine.text);
```

## Интеграция

1. Подключайте файл как локальный статический ресурс проекта; отдельный сервер для диалогов не требуется.
2. Используйте справочник `characters` для подписей и связи персонажей с аватарками. Сами изображения и интерфейс хранятся отдельно.
3. Храните **прогресс игрока отдельно** от сценария. Файл не предназначен для записи пользовательского состояния.
4. Общий финал открывается по условию `finale.unlockCondition = "all_base_dataset_facts_restored"`; это условие должна проверять игровая логика.
5. При изменениях текста сохраняйте существующие `id`, чтобы не нарушить связь с сохранённым прогрессом.

## Что ещё предстоит сделать

В `prologue.tutorial.questionContent` указано `"to_be_created"`: обучающий исторический вопрос ещё не подготовлен. Это **не готовый игровой вопрос**, а явная отметка о незаполненном содержимом. Пролог не должен влиять на прогресс основной коллекции (`outsideMainCatalog: true`, `affectsCollection: false`).

Диалоги — данные сценария, не исполняемый код. Перед выпуском игры рекомендуется автоматически проверять количество глав, уникальность идентификаторов, существование каждого `speaker` и непустоту реплик.
